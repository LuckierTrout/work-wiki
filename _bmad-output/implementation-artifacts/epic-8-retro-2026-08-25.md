## Acceptance verdict

**Rejected.** The original exact-head review at `07332c8` found a forgeable
shell approval, a workspace write that deleted an external file, approved
commands that escaped `agent-workspace/`, a repo-relative MCP entry, and a red
full suite. Those product failures were remediated after this document was
written (actions 1–6, `done` in `sprint-status.yaml`). Story `done` and
remediation `done` still do not accept the epic.

Acceptance still requires a fresh review of an immutable post-fix SHA, then on
that same SHA: typecheck, lint, full Vitest, production build, the exploit
regressions, a rendered Settings/Chat walkthrough, and an MCP launch from a
normal non-repository client cwd. Those remaining gates are tracked as
`epic-8-retro-acceptance-gates`. Further `server.mjs` / `ChatCanvas.tsx` /
Settings splits are `epic-8-retro-architecture-follow-on` and are not
acceptance blockers.

## Open questions

Answered in the remediations and in
`_bmad-output/implementation-artifacts/epic-8-sidecar-runtime.md`:

- The v1 sidecar stays the existing Node ESM process. A Rust Agent sidecar
  would be a new product boundary, not a remediation of this review.
- `mode: deep` is broader retrieval `topK` on this search endpoint. It is not
  Deep Research.
- Absolute loopback `{id}` values resolve only against registered Wiki roots.
  An unregistered filesystem path is `400 invalid_wiki_id`, not silent
  `current`. `agent-workspace/` is not a project id.
- Tool turns use typed citations (`page`, `source`, `graph`, `web`).
  Workspace-only output turns persist without a fake wiki `[n]`.
