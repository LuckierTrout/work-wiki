### Aggregate view

- **Delivery shape — fix now / prevent with story-sized evidence gates.** The epic landed as one 40-file, 5,412-line bundle in a single commit. Its central orchestrator grew from roughly 200 to 955 lines, while `ResearchCanvas.tsx` grew to 361 lines and provider, Settings, lease, route, Worker-consumer, lifecycle, Source, and Ingest behavior moved together. No import cycle was found, and provider vocabulary is appropriately centralized in the client-safe Settings contract, but research state now spans `research-projects.json`, `research-leases.json`, the Page lifecycle, immutable raw Sources, Ingest jobs, and Queue messages without one durable operation record. This repeats the still-open orchestration lesson from Epic 2 and the in-progress delivery/review lesson from Epic 5 (`git_evidence.py`; `src/lib/research-runtime.ts:255-950`; `sprint-status.yaml`).
- **Concurrency and state invariants — fix now / prevent with a linearizable-state convention.** The declared contract says at most three runs and restart-safe tasks. The lease implementation instead documents that it is “NOT LINEARIZABLE,” permits “3-or-occasionally-4,” treats corrupt or unreadable lease state as empty, and grants a slot even when its durable write fails (`spec-6-1-through-6-5-deep-research.md:78-79,211,216`; `src/lib/research-concurrency.ts:24-31,82-96,111-142`). The project transition from `queued` to `collecting` is also a non-atomic read/update; two deliveries can both pass it because a per-project lease is idempotently granted to both (`src/lib/research-runtime.ts:677-753`). These are contract failures, not harmless throttling differences.
- **Success atomicity and truthfulness — fix now / prevent with a durable-operation or outbox pattern.** The Page is written before the project becomes `complete`; Source and Ingest work exists only in process memory until after completion and slot release; every per-Source failure is logged and swallowed. A post-Page registry failure can therefore show `failed` and “Nothing was written,” while a process loss or dispatch failure can leave a `complete` project without the required Sources or Activity jobs (`src/lib/research-runtime.ts:580-638,876-950`). Page frontmatter is built from all search results while synthesis and stored Sources use only successfully fetched sources, overstating evidence (`src/lib/research-runtime.ts:128-141,794-802,877`).
- **Scope and contract alignment — fix now / prevent with one authoritative Wiki-ID contract.** Confirm records `vaultId`, and UI copy says it makes auto-Ingest land in the originating Wiki. The runtime explicitly ignores that value for Page and Source/Ingest routing because the Workbench UUID is incompatible with the existing Knowledge Studio vault identifier. The Research list is owner-wide, not active-Wiki scoped (`spec-6-1-through-6-5-deep-research.md:70,104,146,206`; `src/components/workbench/ResearchCanvas.tsx:112-125`; `src/lib/research-runtime.ts:573-578,893-900`; `src/app/api/research/route.ts:27-40`). The as-built behavior does not satisfy the locked wiki-switch contract.
- **Observed progress versus promised streaming — fix now / prevent with an executable UI semantic.** Query/fetch status is persisted and polled, but model thinking is extracted only after the non-streaming LLM call returns and is stored with terminal completion. The UI’s active “live thinking” branch is therefore unreachable from the real runtime; tests reach it only with fabricated project records (`src/lib/research-runtime.ts:838-853,907-920`; `src/components/workbench/ResearchCanvas.tsx:276-349`). One failed poll clears all rows; that makes `streaming` false and stops the interval, so a transient list failure can end progress updates (`src/components/workbench/ResearchCanvas.tsx:71-103`).
- **Positive controls — accept as implemented.** Current source and tests support Tavily as the default, selectable SerpApi/SearXNG, no normal selected-provider fallback, corrected Firecrawl copy, secret redaction/env precedence, confirm-before-search, Review remaining pending, lifecycle Page instead of memory-proposal, owner auth/read-only refusal, Research independence from the serial Ingest compile lock, and SSRF validation on extracted URLs. These controls remain subject to the end-to-end limits below.

### Adversarial lens

- **Fix now:** make admission and per-attempt execution atomic. Concurrent Queue deliveries can both search, synthesize, spend quota, and race one Page; cross-isolate lease acquisition can exceed three and storage failure fails open (`src/lib/research-concurrency.ts:88-142`; `src/lib/research-runtime.ts:255-310,677-753`).
- **Fix now:** fence cancel, delete, restart recovery, and Page commit. DELETE removes the row without cancellation or lease release; `cancelRequested` projects are skipped by reconciliation; cancel during `ready` releases capacity while synthesis may still run; and the last cancel check is not atomic with Page write (`src/app/api/research/[id]/route.ts:63-76`; `src/lib/research-runtime.ts:313-334,382-405,861-892`).
- **Fix now:** restrict the mutation surface. Owner PATCH accepts client-supplied lifecycle status, synthesis, source URLs, and Page slugs. `/run` treats malformed JSON or any unrecognized action as “start” and accepts a provider override even though Settings is declared authoritative (`src/app/api/research/[id]/route.ts:17-59`; `src/app/api/research/[id]/run/route.ts:32-45`). A failed project retry also prefers the stale recorded provider over current Settings (`src/lib/research-runtime.ts:279-299`).
- **Fix now:** validate completion evidence. The runtime does not validate that synthesis citations are restricted to supplied URLs, and the one-block `<thinking>` parser can leave additional or unmatched private reasoning tags in publishable content (`src/lib/research-runtime.ts:246-252,838-878`).

### Edge-case lens

- **Fix now:** handle the death points between Page commit, completion persistence, Source storage, job creation, Queue dispatch, and inline Ingest. Each needs an idempotent retryable state rather than a success row or contradictory failure sentence (`src/lib/research-runtime.ts:580-638,876-950`).
- **Fix now:** preserve cancellation and deletion semantics across timing edges: deletion after the worker’s initial read, cancellation during synthesis, cancellation between the last check and Page write, and a cancelled worker that dies before observing the request (`src/lib/research-runtime.ts:313-405,677-753,861-892`).
- **Fix now:** keep active tasks visible after transient polling failure and fence a Wiki switch during Graph/Review create-then-run. In particular, Review’s stale-response check can return after project creation but before `/run`, leaving an orphan draft (`src/components/workbench/ResearchCanvas.tsx:71-103`; `src/components/workbench/ReviewCanvas.tsx:121-145`).
- **Reconcile before acceptance:** non-Tavily extraction uses the kernel’s 100,000-character application cap even though the declared criterion forbids any app-imposed truncation before synthesis (`spec-6-1-through-6-5-deep-research.md:72,98,208-209`; `src/lib/constants.ts:25`; `src/lib/fetch.ts:150-151,329-330`; `src/lib/research-providers.ts:297-318`). Either remove the cap for this path or obtain an authoritative contract revision.

### Verification-gap lens

- **Fix now:** add barrier-controlled tests for two simultaneous `runResearchProject` deliveries and for separate-isolate contenders racing for the final slot. Existing concurrency tests await acquisitions sequentially, and redelivery tests exercise only a second call after the first transition or completion (`src/lib/__tests__/research-concurrency.test.ts:46-59`; `src/lib/__tests__/research-runtime.test.ts:474-547`).
- **Fix now:** execute the complete create → run route → task parser → task consumer → runtime path. The route test mocks both dispatch and runtime, task parser/consumer suites have no successful `run-research` case, and browser coverage deliberately stops at an unconfigured-provider refusal (`src/lib/__tests__/research-run-route.test.ts:77-94`; `e2e/workbench-owner.spec.ts:239-257`).
- **Fix now:** fault-inject cancellation during synthesis, claimed-queue restart, writable DELETE with a held slot, post-Page registry failure, and each Source/Ingest handoff. Current success coverage makes all dependencies resolve, while failure coverage stops before Page write (`src/lib/__tests__/research-runtime.test.ts:158-195,345-413,741-765`).
- **Defer only after the blocking paths are closed:** add live provider/runtime proof for Tavily and at least one extract-based provider. No live credentials were available during this retrospective, so mocked provider/LLM tests cannot establish provider API compatibility or deployed R2/Queue behavior.
