## Findings

The aggregate passes and full-diff `bmad-code-review` ran architecture/duplication, growth/pattern, specification reconciliation, Blind Hunter, Edge Case Hunter, Verification Gap, and Acceptance Auditor views. Review triage produced 30 actionable findings (3 contract decisions and 27 patchable defects); four duplicates or unsupported low-value claims were dismissed. The related findings are consolidated below.

### Release and runtime gates

1. **The committed checkout does not build or typecheck, and the full suite is red.** TypeScript reports seven Epic 3 errors, `next build` stops on `ChatCanvas.tsx:416`, and the Workbench mode/URL suite has one Epic 3 regression. Disposition: **fix now**. Provenance: direct verification.

### Trust, authority, and durability

2. **The loopback sidecar can disclose a local provider secret to a caller-selected endpoint.** It returns wildcard CORS (`sidecar/server.mjs:169-173,487-503`), accepts `body.model.baseUrl` (`:369-450`), resolves a local secret, and sends it to that URL (`:283-325`). The architecture reviewer reproduced this using only a sentinel key and a local capture server; no real credential or external host was used. Disposition: **fix now**.

3. **The owner-only kernel boundary is inconsistent and `wikiId` is ceremonial.** Retrieve/Search use `requireOwnerPrincipal`, while Conversation collection/item/messages and Save use `getPrincipal` (`src/app/api/chat/conversations/**`; `src/app/api/chat/conversations/[id]/save/route.ts:25-29`). Retrieve/Search reject only filesystem-looking IDs, accept other invalid strings, and never bind retrieval to the route's `wikiId` (`src/app/api/v1/projects/[wikiId]/{retrieve,search}/route.ts`). Disposition: **fix now**.

4. **Conversation persistence can lose updates across Cloudflare isolates.** Every Conversation for an owner lives in one JSON object and all mutations are read-modify-write under an explicitly process-local lock (`src/lib/chat.ts:139-181,199-363`; `src/lib/lock.ts:14-17`). Create, rename, delete, persist, and Regenerate can overwrite one another across isolates. Disposition: **fix now**.

### Retrieval and citation contracts

5. **Cited-or-silent behavior is advisory rather than enforced.** The sidecar returns opaque model content plus every assembled citation without verifying a mapped `[n]` (`sidecar/server.mjs:446-465`); Chat persists the combination (`ChatCanvas.tsx:416-425`), renders all candidates as references (`:695-718`), and Save promotes them as provenance. Missing, invented, duplicate, unused, or out-of-range citations pass the current seam. Disposition: **fix now**.

6. **The history budget is reported but not applied.** Assembly computes a packed `historyText` under the 20% slot, but returns the original `historySlice`, which Chat sends to the sidecar (`src/lib/wiki-retrieve.ts:614-627,640-658`; `ChatCanvas.tsx:353-363`). If packing is wired through, it must retain the newest messages rather than the oldest. Disposition: **fix now**.

7. **Page budget accounting excludes numbered metadata, while the full-body and hard-budget criteria conflict for oversized documents.** A first oversized body is character-sliced, wrapper overhead is added later, and the corrective loop cannot trim a single remaining Page (`src/lib/wiki-retrieve.ts:589-613`). This can violate both the 60% slot and “full Page or Source bodies.” Disposition: **human contract ruling, then fix**.

8. **Chat and Search duplicate the retrieval orchestration and already rank differently with vectors.** Search slices tokenized seeds before vector merge; Chat does not (`src/lib/wiki-retrieve.ts:437-456,562-578`). Both otherwise call the same lower-level primitives, but the declared one-pipeline contract is not met. Disposition: **fix now**.

9. **Each request walks the whole corpus, repeats storage reads, and can fan out without bounds.** Retrieval reads every Page and Source, then graph expansion re-reads every Page through `Promise.all` (`src/lib/wiki-retrieve.ts:149-247,343-371`), contrary to the repository's bounded-concurrency convention. Distinct Sources with identical bodies are also collapsed to the first encountered identity (`:204-209`), and a legacy-list failure prevents the independent snapshot walk (`:211-250`). Disposition: **fix now**.

### Chat state and provider behavior

10. **Regenerate uses stale history and destroys the prior answer before replacement succeeds.** The durable pair is retracted, React state is scheduled, and `sendTurn` immediately reads the old `messages` closure (`ChatCanvas.tsx:301-307,473-486`; `src/lib/chat.ts:345-361`). Failure, Stop, or missing credentials leaves the old answer deleted. Disposition: **fix now**.

11. **Chat/Search lifecycle races can swap or lose user state.** `ChatCanvas` is unmounted on mode change, losing drafts and not aborting an active sidecar request (`ModeCanvas.tsx:130-149`; `ChatCanvas.tsx:113-178`). Conversation loads/persists and Search requests have no latest-request fence; slider patches can complete out of order. Disposition: **fix now**.

12. **Incomplete or invalid sidecar outcomes can become misleading durable state.** A stream that ends without `done` persists the coverage-missing sentence (`ChatCanvas.tsx:404-426`); a missing-model early return leaves the optimistic user frame (`:293-296,340-342`); the sidecar lacks provider timeouts/response bounds and does not validate primitive bodies, malformed history rows, or an empty prompt with non-empty context (`sidecar/server.mjs:175-201,213-280,369-445`). Disposition: **fix now**.

13. **Thinking is post-generation framing, not streaming, and Chat readiness has two authorities.** The provider call blocks; Thinking is extracted and emitted as one complete frame after generation (`sidecar/server.mjs:204-210,413-418,446-465`). The kernel can block a locally configured sidecar, while kernel-ready settings can fail because the sidecar resolves a different local configuration (`wiki-retrieve.ts:514-527`; `ChatCanvas.tsx:340-363`; `sidecar/server.mjs:87-125,292-309`). Disposition: **human ruling** on streaming acceptance and the authoritative readiness contract, then fix or explicitly reconcile Story 3.8.

### Save and API integrity

14. **Save can pair arbitrary client text with another answer's citations and discards Sources-only evidence.** The route prefers request content but reads citations from the last persisted assistant; it filters out all `raw/sources/...` and nested wiki paths (`src/app/api/chat/conversations/[id]/save/route.ts:42-70`). Disposition: **fix now**.

15. **Save is a non-idempotent multi-write sequence with incomplete failure handling.** Page write, raw snapshot, job creation, and dispatch occur sequentially without compensation or an idempotency key; the inline callback omits `jobId`; the route does not check `ingestResponse.ok`; double-click has no in-flight fence (`save/route.ts:66-127`; `ChatCanvas.tsx:489-500`). A 500 can follow durable mutation, or the route can claim queued success after rejection. Disposition: **fix now**.

16. **Turn and route validation permits malformed state or misleading success.** With one message slot left, a two-frame turn can persist only the user; the messages route accepts assistant-only or misordered batches; malformed JSON becomes 500; Conversation numeric fields of the wrong type are silently ignored (`src/lib/chat.ts:304-338`; `messages/route.ts:44-128`; Conversation collection/item routes). Disposition: **fix now**.

### Verification and maintainability

17. **The most important positive paths are not executed by tests.** There is no deterministic successful-provider SSE aggregation test, Save-route-to-Ingest-to-retrieval test, configured-owner negative test for Conversation/Save, citation/Search click-to-Preview test, or executable Thinking viewport/reload test. Several current checks only inspect source strings (`workbench-epic3.test.ts:212-253`). Disposition: **fix now**.

18. **Implementation growth concentrated across three change axes.** `ChatCanvas.tsx` grew to 751 lines, `wiki-retrieve.ts` to 664, and `sidecar/server.mjs` to 523; together they contain 46.6% of epic additions. `ChatCanvas.sendTurn` owns retrieval, transport, SSE parsing, persistence, cancellation, and recovery. Cross-runtime SSE names, Wiki-ID rules, and fixed copy are hand-duplicated, and global `validateSlug` was widened for one query-page path. Disposition: **defer extraction until correctness is restored, but keep the existing Epic 2 orchestration item open**.

## Action items

All items are **proposed and open**. This retrospective did not patch product code, revise the implementation spec, or touch `deferred-work.md`.

1. **Close the sidecar credential-exfiltration boundary.** Owner: Sidecar / security. Allow only trusted Workbench origins, never accept caller-selected provider endpoints or provider identity for secret-bearing calls, validate request objects/history/query, and add provider deadlines and response-size bounds.
2. **Restore release gates and add an Epic 3 browser gate.** Owner: Workbench / QA. Fix the seven TypeScript errors, production build, full-suite mode regression, and lint warning; add authenticated Chat/Search/Save coverage that runs beyond source-string assertions.
3. **Enforce one owner and Wiki authority.** Owner: Kernel / auth. Apply the configured-owner gate to every Conversation/message/Save route, validate `current | UUID`, verify existence, and bind retrieval/search to the selected Wiki.
4. **Make Conversation updates durable and atomic.** Owner: Kernel / storage. Replace process-local JSON read-modify-write with an isolate-safe conditional/transactional strategy; persist whole turns atomically and reject malformed ordering or capacity overflow.
5. **Enforce citation integrity at the generation/persistence seam.** Owner: Chat / retrieval. Require each positive answer to contain at least one valid assembled `[n]`, reject invented or unused mappings, persist/render only cited rows, and validate citation namespaces before Save.
6. **Unify retrieval and enforce its budgets.** Owner: Retrieval. Route Chat and Search through one orchestration, apply the 20% history cap to the actual structured messages while retaining newest history, include wrapper overhead in page accounting, and add saturated 60/20/5/15 tests.
7. **Resolve full-body versus hard-budget semantics.** Owner: Product / architecture. Decide whether an oversized Page is excluded, chunked as a Source-derived unit, or allowed to exceed its slice; then reconcile Story 3.3 and implement the ruling without silently truncating a promised full body.
8. **Bound corpus work and preserve Source identity.** Owner: Retrieval / storage. Use indexed or cached retrieval, bounded concurrency, and one read per artifact; walk legacy and snapshot sources independently; retain every immutable Source identity instead of de-duplicating by body.
9. **Make Regenerate and UI transitions failure-safe.** Owner: Workbench / Chat. Generate from the retracted history, replace the pair atomically or roll it back, preserve per-Conversation drafts across modes, abort on unmount, fence stale Conversation/Search responses, and serialize slider/config patches.
10. **Define and implement the sidecar streaming/readiness contract.** Owner: Product / sidecar. Decide whether Story 3.8 requires real upstream incremental Thinking and which runtime owns Chat readiness; implement that contract or explicitly revise the criterion. Require `done` before persistence and clear optimistic frames on all early exits.
11. **Make Save-to-Wiki one truthful, idempotent lifecycle.** Owner: Wiki kernel / Ingest. Save a persisted assistant message by identity with its exact Page and Source provenance, fence duplicate clicks/retries, propagate `jobId`, check dispatch responses, and make partial failure resumable or compensating.
12. **Add executed contract tests and then reduce orchestration drift.** Owner: QA / maintainers. Cover successful-provider SSE aggregation, configured-owner negatives, citation/Search Preview clicks, Thinking viewport/reload, and Save→Ingest→retrieve. After blockers close, split Chat transport/state/rendering, retrieval corpus/ranking/packing, and sidecar config/provider/HTTP seams; generate or comprehensively parity-test cross-runtime protocol constants and use a query-specific slug validator.

## Acceptance verdict

**Machine verdict: rejected. Criteria: declared.**

All 11 stories are marked `done`, so this is not an unfinished-story rejection. The epic fails declared criteria and release evidence because:

- a web origin can direct the unauthenticated loopback sidecar to disclose a local provider secret;
- the checkout does not typecheck or build, and the full suite has an Epic 3 regression;
- owner-only kernel routing and Wiki selection are not enforced consistently;
- actual history can exceed its declared slot, page wrapper overhead can exceed budget, and Chat/Search are not one retrieval pipeline;
- cited-or-silent behavior is not enforced, and Save can mismatch content/evidence or discard Sources-only provenance;
- Conversation durability is process-local on a multi-isolate deployment;
- Regenerate is stale-history and destructive-on-failure;
- Thinking is not incremental, and the central successful Chat/Save flows lack end-to-end evidence.

No human override was supplied. Acceptance can be reconsidered after the security boundary and release gates close, Actions 3–11 have execution evidence, and the three contract rulings below are resolved.

3. Is Chat readiness authoritative in the kernel Settings store, the local sidecar's secret/config state, or an explicit handshake combining both?
