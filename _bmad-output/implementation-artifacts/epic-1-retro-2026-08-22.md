## Findings

### 1. Blocking — Story 1.7's production counter does not satisfy its declared contract

**Evidence.** The epic says a successful page or Schema write makes `dataVersion` "bump as a monotonic integer" (`_bmad-output/planning-artifacts/epics.md:458-468`), and the Story 1.7 acceptance criterion strengthens that to "exactly one higher than before" (`_bmad-output/implementation-artifacts/spec-1-7-dataversion-workbench-refresh.md:260-265`). The current implementation says its lock is process-local, two Worker isolates can collapse increments, an eventually consistent read can move the stored counter backwards, and a failed config-store write returns `0` without moving the signal (`src/lib/data-version.ts:33-63,117-142`). The fail-soft choice is intentional and protects a page write that already landed, but it is not the exact, monotonic production behavior the declared acceptance criterion promises.

- Instance disposition: **fix now / reconcile before acceptance**. Either provide a provider-atomic monotonic signal with cross-isolate evidence, or obtain an explicit human architecture/product decision to revise the criterion to the weaker notification semantics actually implemented.
- Prevention: state consistency and failure semantics in the acceptance criterion itself; do not combine "exactly once/monotonic" with a documented fail-soft, eventually consistent implementation unless the exception is part of the contract.

### 2. High-priority follow-up — the raw-source read boundary still falls back to a shared legacy root

**Evidence.** `resolveRoot` selects the flat root whenever the tenant silo is readable but empty (`src/lib/workbench-files.ts:147-174`). For `raw/`, that makes both filenames and bytes from the transitional shared tree visible through the Workbench. `DW-40` records the same problem and already carries the 2026-08-22 decision to remove the fallback for `raw/` only (`_bmad-output/implementation-artifacts/deferred-work.md:356-364`).

- Instance disposition: **fix now, through the existing DW-40 decision**, before Epic 2 begins accepting real Sources. The retrospective does not duplicate or mutate the orchestrator-owned ledger.
- Prevention: every storage fallback must declare whether it is a migration aid or an authorization boundary; shared-root compatibility must never be inherited implicitly by new content types.
