## Findings

### Spec-to-implementation and behavior

#### 1. The authenticated Workbench does not compile

`Workbench.tsx` is a client component, but Epic 2 imports delete copy and route constants from the server-side cascade module (`src/components/workbench/Workbench.tsx:1,103-110`). That module imports `action-items`, which imports the integration outbox and storage stack (`src/lib/source-cascade.ts:10-16`; `src/lib/action-items.ts:1-6`). Both `next dev` and `next build` therefore try to bundle Node `net`, `node:fs/promises`, and `node:path` into the client. The production build fails with the exact import trace `Workbench → source-cascade → action-items → integration-outbox → url-safety`; all three authenticated Workbench E2Es fail before the shell renders.

- Disposition: **fix now**. Move client-safe copy/route constants to a client-safe module and keep cascade execution server-only.
- Provenance: live build/browser verification; adversarial boundary review.

#### 2. Cross-owner SHA hits can disclose an inaccessible Source and suppress the caller's ingest

The Intake route treats any global SHA lookup as a successful skip (`src/app/api/workbench/intake/route.ts:254-290`). `recordSourceResee` can return `null` when the matched page is inaccessible, but the route still returns the matched slug and stored path and never stores/queues the caller's own Source (`:257-288`). The lower-level ingest path correctly falls through when the re-see is denied (`src/lib/ingest.ts:1767-1783`); the new route does not.

- Disposition: **fix now**. Only skip after an authorized re-see; otherwise invalidate/fence the hit and continue with the caller's own Source without exposing the match.
- Provenance: adversarial and edge-case lenses.

#### 3. Intake violates byte identity and reports declined work as queued

File Intake trims text before hashing and storage (`src/app/api/workbench/intake/route.ts:127-158`), so leading/trailing-byte changes disappear despite Story 2.7's any-byte-change contract (`_bmad-output/planning-artifacts/epics.md:665-682`). Folder paths are slugified and can collide; an occupied path with different bytes is declined (`src/lib/raw.ts:119-143,198-227`), while the client ignores successful response fields such as `queued: false`/`skipped: true` and reports any 2xx as stored/queued (`src/lib/workbench-intake-client.ts:128-155`).

- Disposition: **fix now**. Preserve original bytes, make sanitized-path collisions explicit, and model stored/skipped/not-queued/refused outcomes separately in the client.
- Provenance: adversarial and edge-case lenses; Story 2.1/2.2 acceptance criteria.

#### 4. The serial queue and retry state machine are not durable

The owner LLM lock is process-local (`src/lib/lock.ts:14-17`; `src/lib/ingest.ts:1593-1616`). The consumer processes one delivered batch sequentially but its queue config does not cap concurrent batches (`workers/task-consumer/index.ts:225-229`; `workers/task-consumer/wrangler.jsonc:26-34`), so separate Worker isolates can overlap. A transient task failure is immediately stored as `failed` before the route returns a retryable 500 (`src/app/api/tasks/run/route.ts:565-579,625-632`); Activity exposes manual Retry for every failed row (`src/app/api/workbench/activity/route.ts:37-55`). Manual and automatic deliveries can therefore overlap. Job patches themselves are unlocked read-modify-writes (`src/lib/ingest-jobs.ts:212-227`).

- Disposition: **fix now**. Provide a durable owner-serial claim, distinguish retrying from terminal failure, and make job transitions atomic.
- Provenance: spec reconciliation, adversarial, and edge-case lenses.

#### 5. The two-step contract silently degrades and automatic Generation retry repeats Analysis

Analysis catches every provider error and substitutes an empty artifact (`src/lib/ingest.ts:1563-1581`), after which Generation proceeds (`:1598-1615`). That contradicts “Generation starts only after Analysis succeeds” (`_bmad-output/planning-artifacts/epics.md:638-643`). Queue redelivery reuses Analysis only when the original immutable task already carried `reuseAnalysis`; a Generation failure does not update that message, so automatic retry runs Analysis again (`src/app/api/tasks/run/route.ts:311-335`).

- Disposition: **fix now**. Fail/retry an unsuccessful Analysis and discover a valid persisted Analysis artifact on every tracked retry.
- Provenance: spec reconciliation and adversarial lenses.

#### 6. Plaud origin is not durable Source provenance

Plaud `origin` exists on the job/task and suppresses Todo extraction (`src/lib/ingest-jobs.ts:77-87`; `src/app/api/tasks/run/route.ts:468-481`), but `SourceEntry` has no origin field and the generated Page's `sources[]` ignores `options.origin` (`src/lib/ingest.ts:1942-1956`). Terminal jobs are garbage-collected, so the provenance disappears. Existing tests prove job/task stamping and Todo suppression, not durable page provenance.

- Disposition: **fix now**. Add the approved durable provenance representation and verify it after job GC.
- Provenance: spec reconciliation and verification-gap lens; Story 2.4 criteria (`epics.md:581-593`).

#### 7. Source identity does not join Intake, generated Pages, and cascade delete

For folder imports, the generated concept Page records `text-paste` plus a content hash, not the known stored path (`src/lib/ingest.ts:1942-1956`). Cascade keys for `raw/sources/<tree>/<file>` contain paths and leaf names but not that hash (`src/lib/source-cascade.ts:42-74`), so the summary may delete while the sole-source concept Page survives. The test constructs a hashed path whose filename and `raw_id` already match instead of exercising folder Intake through delete (`src/lib/__tests__/lifecycle.test.ts:1152-1227`). The cascade's third finder can also identify a Page by `source_url`, `path`, or `slug` but neither deletes a sole-source Page on that basis nor clears the matched field (`src/lib/source-cascade.ts:55-99,131-165`).

The same operation scans the global page list without an owner check (`src/lib/source-cascade.ts:101-120`), uses broad filename/title keys that can match unrelated Sources (`:42-52`), and deletes only the selected raw path even though ingest writes additional raw copies (`src/lib/ingest.ts:1899-1956`).

- Disposition: **fix now**. Define one canonical Source identity carried through page provenance, summary, indexes, Todos, and delete; enforce owner scope; remove every explicitly linked raw object; add a real folder-ingest-to-delete test.
- Provenance: spec reconciliation plus all three `bmad-review` lenses.

#### 8. Cancel/delete promises are vulnerable to races and partial application

Ingest checks cancellation once immediately before a multi-effect page lifecycle write (`src/lib/ingest.ts:2155-2170`), so a cancel arriving after the check can still commit Pages. Existing tests cancel before mocked ingest or inject `IngestCancelledError`; none runs the real write race. Deleting a Source does not cancel or tombstone queued/processing jobs (`src/lib/source-cascade.ts:101-168`), so a worker can recreate pages after the owner confirms deletion. Cascade itself has no transaction/resume marker; a mid-loop failure leaves partial page mutations and Source bytes in mixed states.

- Disposition: **fix now**. Make commit/cancel state atomic, fence deleted Sources from queued work, and make cascade resumable or transactional.
- Provenance: edge-case, adversarial, and verification-gap lenses.

#### 9. Successful-page bookkeeping is neither resumable nor schema-driven

The primary Page, including `content_sha256`, is committed before bookkeeping (`src/lib/ingest.ts:1927-1928,2160-2197`). If bookkeeping then fails, a cold retry rebuilds the SHA index and returns skipped before repairing the missing Overview or Source summary. No test injects that failure and retries after index rebuild. `ensureSourceSummary` awaits `loadPageTemplates()` but ignores the result and hardcodes Key Points/Details/Sources (`src/lib/ingest-bookkeeping.ts:87-128`), reproducing the drift pattern prohibited by `.yoyo/learnings.md`. It also regenerates Overview before creating the current summary (`src/lib/ingest-bookkeeping.ts:194-205`).

- Disposition: **fix now**. Add a durable bookkeeping-complete boundary or idempotent repair path, render from the executable Schema template, and decide/document whether summaries belong in Overview before fixing order.
- Provenance: adversarial, edge-case, verification-gap, and spec-reconciliation passes.

#### 10. Sources “progressive first paint” and Activity progress do not represent their declared systems

The server awaits a breadth-first file walk up to the 2,000-node cap before rendering (`src/app/page.tsx:98-107`; `src/lib/workbench-files.ts:192-241`); `SourcesTree` windows only the already-complete client list (`src/components/workbench/SourcesTree.tsx:37-60`). This preserves client scroll position but does not satisfy “first paint does not wait on every row” (`epics.md:746-757`). Activity's progress denominator is up to 100 retained historical rows, including terminal jobs, rather than current queue depth (`src/app/api/workbench/activity/route.ts:37-55`; `src/lib/workbench-activity.ts:72-87`).

- Disposition: **fix now or reconcile criteria**. Paginate/stream the server listing and derive progress from active queue state, or explicitly weaken the acceptance language.
- Provenance: spec reconciliation.
